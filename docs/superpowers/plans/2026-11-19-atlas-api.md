# Atlas API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans task-by-task. User overrides mandatory TDD. Existing tests require permission to change.

**Goal:** Persist the personal workspace, enforce task rules, and coordinate local repository creation.

**Architecture:** Fastify owns SQLite through Drizzle and exposes HTTP routes plus one Worker WebSocket endpoint. It never runs Git. Build against shared contracts and a simulated Worker until integration.

**Tech Stack:** Node.js/TypeScript, Fastify, `@fastify/websocket`, SQLite/Drizzle, shared Zod schemas, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-19-atlas-local-mvp-design.md`; exact interfaces in `2026-11-19-atlas-foundation-and-integration.md` alongside this plan.

## Global Constraints

- Run in WSL on loopback. Only API owns application data.
- Implement the frozen contract verbatim; coordinate contract changes centrally.
- No TDD requirement. Existing tests, fixtures, snapshots and check configuration require permission to modify or bypass.
- New task only in Backlog; all fields editable there, only description in To do/Working, none in Done. Moves remain allowed.
- Assignment never launches a Worker or agent. No Git execution, cloning or terminal handling.

## Review Focus

1. Foreign browser origins must be rejected before a mutation (task 1).
2. Wrong-project version references must never leak or reassign tasks (task 2).
3. A patch combining description with forbidden fields must fail atomically (task 2).
4. Worker restart/disconnect must not strand false online state (task 3).
5. Duplicate/conflicting results must not create two versions or overwrite outcomes (task 3).

## Task 1: Persistent API and basic resources

**Files:** `apps/api/src/{server,app,config}.ts`, `src/db/{client,schema,migrate}.ts`, `drizzle/` migrations, `src/http/errors.ts`, `src/projects/{routes,service}.ts`, `src/versions/routes.ts`, `src/workers/routes.ts`, `tests/resources.test.ts`, `tests/origins.test.ts`, `.env.example`.

**Interfaces:** `buildApp(options: ApiOptions): Promise<FastifyInstance>`; options contain DB path, worker token, allowed origin, injected clock if needed. `close()` closes DB, sockets and timers. `createProject(input:ProjectCreate): Promise<{project:Project,operation:Operation|null}>` returns existing projects ready, local projects pending. Protocol definitions are imported, not redefined.

- [ ] Implement configuration validation and DB migrations. Use a compatible SQLite driver selected during foundation setup; enable foreign keys. Tables: projects, versions, workers, tasks, operations. Uniqueness: worker id, version `(projectId,name)`, operation id. Seed `human:vladi` idempotently; invalidate persisted Atlas presence on startup. Preserve all data on restart.
- [ ] Implement list/get/create projects and versions plus worker list. Existing Git URL is stored without contact; create initial `v0.1` transactionally. Local project creation validates an online capable Worker and stores project/operation before dispatch; task work and adding versions require ready project. Temporary dispatcher may be injected for this task, never mark local project ready without result.
- [ ] Use shared strict schemas for body/params and structured errors. Reject untrusted Origin headers server-side, not only via CORS response headers; mutating requests require JSON content type. Bind loopback and validate expected local Host names. Allow non-browser local clients without Origin; Worker upgrade uses bearer token and rejects browser Origin. Log request ids without tokens/secret bodies.
- [ ] Add tests using Fastify injection and temporary SQLite files. Assert `v0.1` appears once after restart; duplicate version returns 409; project list persists; unsafe credentials/invalid URL syntax return 400; an unrelated Origin POST is 403 with no new DB row; read-only worker list includes Vladi once. Verify routes return exact contract DTOs.
- [ ] Run `pnpm --filter @atlas/api test`, `pnpm --filter @atlas/api typecheck`, `pnpm --filter @atlas/api lint`. Expected: passing. Commit `feat(api): persist projects versions and workers`.

## Task 2: Tasks, field rules and transactional ordering

**Files:** `apps/api/src/tasks/{routes,service,ordering}.ts`, `tests/{tasks,task-ordering}.test.ts`.

**Interfaces:** `createTask(projectId:string,versionId:string,input:TaskCreate):Promise<Task>`; `patchTask(taskId:string,input:TaskPatch):Promise<Task>`; `moveTask(taskId:string,input:TaskMove):Promise<Task>`. Services use the API-owned DB context; return DTOs and domain errors mapped by HTTP layer.

- [ ] Implement scoped list/create tasks with title validation, empty description, Task/Medium/unassigned defaults and Backlog status. Require version membership and ready project. Append to column; do not dispatch any Worker command.
- [ ] Implement atomic patch using stored status and revision. Reject any forbidden field even if submitted value is unchanged. Backlog version change stays within same project and appends to destination Backlog. Allow description only in todo/working; reject all patches in done. Validate assignee exists, including offline Atlas workers.
- [ ] Implement moves using frozen `beforeTaskId` semantics, transactionally compacting positions and revisions. Source/destination may be identical. Reject stale revision or foreign/missing anchor; status move cannot include arbitrary fields. Status may change from any of the four columns to any other. Revision conflicts never silently overwrite newer data.
- [ ] Add table-driven tests over every status/field and all 16 status transitions. Representative assertions: mixed `{description:'new',priority:'high'}` patch to Working yields 403 and leaves description unchanged; moving Done→Backlog then patching title succeeds; patch version from another project fails without relocation; two updates with same revision yield one success and one 409. Cover empty destination, self-anchor, ordering persistence, unrelated anchors, duplicate titles, and forbidden status key in creation.
- [ ] Run full API tests, typecheck and lint; expected all pass. Commit `feat(api): enforce task editing and movement rules`.

## Task 3: Worker registry and durable repository operations

**Files:** `apps/api/src/workers/{gateway,registry}.ts`, `src/operations/{service,routes}.ts`, `tests/{worker-gateway,operations}.test.ts`, `tests/helpers/simulated-worker.ts`.

**Interfaces:** `WorkerRegistry.send(workerId:string,message:ApiToWorkerMessage):boolean`; `WorkerRegistry.isOnline(workerId:string):boolean`; `dispatchPending(workerId:string):Promise<void>`; `applyResult(workerId:string,message:CommandResult):Promise<void>`. Message type aliases come from contracts. Registry does not own DB state outside service calls.

- [ ] Implement upgrade authentication, frame limits, registration deadline, stable-id checks, protocol validation, heartbeat expiry and disconnect cleanup. Duplicate live worker id is rejected. Worker identity derives from authenticated/registered connection, never arbitrary result payload. Reject registration as the human id. Keep offline metadata for assignments.
- [ ] Wire pending local project dispatch after DB commit. If Worker disappears between validation and dispatch, retain pending operation and `connectionLost:true`; dispatch same id after reconnection. Persist acceptance and results. Result success atomically marks project ready, stores path, and creates `v0.1`; failure/needs-attention updates both project and operation appropriately. Ack only after persistence. Send/read messages only after handlers are registered.
- [ ] Validate result local path against the registered workspace and operation target using POSIX path semantics; reject mismatches. API does not inspect Worker filesystem. Reject result from wrong Worker or unknown command; identical terminal result is idempotent, conflicting result returns protocol error. No transition from terminal state back to accepted/pending on stale messages.
- [ ] Add real WebSocket integration tests with simulated Worker and temporary DB: missing token, browser Origin, unsupported version, malformed frames, duplicate identity, missed heartbeats, pending redispatch, duplicate results, foreign command result, conflicting terminal result, result-before-ack disconnect. Assert exactly one initial version and preserved outcome. Verify registration changes are reflected in HTTP worker list.
- [ ] Run API suite, lint, typecheck and build. Commit `feat(api): coordinate worker repository operations`. Hand over simulated-worker fixtures and verified HTTP/WS examples for integration without modifying another app.
